# Inside the GPT Architecture

> *"The architecture gives GPT its ability to learn. The parameters determine what it has learned."*

---
# The Problem

We've now seen the complete learning process.

The model:

- Makes predictions.
- Measures mistakes.
- Updates parameters.
- Repeats this process billions of times.

But one important question remains.

> **After all this training, where does the knowledge actually go?**

Is it stored inside the dataset?

Inside the source code?

Inside the architecture?

Or somewhere else?

---

# Intuition

Imagine buying a brand-new notebook.

The notebook already has:

- Pages
- Cover
- Binding

But it contains no knowledge.

As you study,

you begin writing on those pages.

Eventually,

the notebook becomes full of information.

Notice something important.

The notebook itself never changed.

Only what was written inside it changed.

GPT works in exactly the same way.

The architecture stays the same.

The parameters change.

---

# Architecture vs Knowledge

Many beginners think:

> GPT becomes smarter because engineers continuously redesign it.

That's not how training works.

The architecture is designed **once**.

Training then updates the parameters inside that architecture.

Think of it like a house.

The blueprint remains the same.

Only the furniture inside changes.

---

# Before Training

```text
GPT Architecture

↓

Random Parameters

↓

No Knowledge
```

At this stage,

the model is simply a mathematical structure.

It has no understanding of language.

---

# After Training

```text
GPT Architecture

↓

Learned Parameters

↓

Language Knowledge
```

The architecture is identical.

Only the parameter values have changed.

---

# Where is Knowledge Stored?

The answer is surprisingly simple.

Knowledge is **not** stored in:

❌ The dataset

❌ The source code

❌ The tokenizer

Knowledge is stored inside the model's **learned parameters**.

Every time Gradient Descent updates a weight,

the model remembers a tiny amount.

Billions of tiny updates eventually become intelligence.

---

# Mathematical Perspective

During training,

only the parameters are updated.

Conceptually, we can think of this as:

```math
\theta_{\text{new}}
=
\theta_{\text{old}}
-
\eta\nabla L
```

where:

- **θ** → All learnable parameters of the model
- **η** → Learning rate
- **∇L** → Gradient of the loss

> Notice that the architecture itself does not change—only the values of the parameters.

# Worked Example

Imagine two students buying the exact same textbook.

The book's structure is identical.

The chapters are identical.

The pages are identical.

After six months:

One student has highlighted important concepts, written notes, and solved every exercise.

The other student has left every page blank.

The books are structurally the same.

But one now contains much more useful information.

GPT works similarly.

Every trained GPT model shares the same architecture.

What makes them different is the values stored in their parameters.

---

# Common Misconceptions

### ❌ The architecture stores knowledge.

No.

The architecture defines *where* learning happens.

The parameters store *what* has been learned.

---

### ❌ Training redesigns the model.

No.

Training updates parameter values.

The architecture remains unchanged.

---

### ❌ The dataset becomes part of GPT.

No.

The dataset is only used during training.

After training,

the learned patterns remain inside the parameters.

# Key Takeaways

- The architecture is designed before training.
- Training changes parameter values, not the architecture.
- Knowledge is stored inside learned parameters.
- GPT consists of embeddings, transformer blocks, and an output layer.
