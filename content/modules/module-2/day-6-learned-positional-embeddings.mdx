## The Big Idea

Imagine the sentence `I Love AI`. The tokenizer produces token IDs — and alongside them, GPT also creates **Position IDs**.

<TokenMapping
  title="Token → Position Assignment"
  fromLabel="Token"
  toLabel="Position ID"
  items={[
    { from: "I",    to: "0" },
    { from: "Love", to: "1" },
    { from: "AI",   to: "2" },
  ]}
/>

Position IDs are not learned — they are simply generated in order: `0, 1, 2, 3, ...`

---

## But Position IDs Have the Same Problem

Just like Token IDs, Position IDs are integers.

Does the number `2` contain useful positional information? No — it is only an identifier.

So GPT converts Position IDs into vectors as well.

---

## Positional Embedding Matrix

Exactly like the token embedding matrix, GPT has another learnable matrix:

<TokenMapping
  title="Positional Embedding Matrix"
  fromLabel="Position ID"
  toLabel="Positional Vector"
  items={[
    { from: "0",    to: "[P₀] — random → learned" },
    { from: "1",    to: "[P₁] — random → learned" },
    { from: "2",    to: "[P₂] — random → learned" },
    { from: "...",  to: "..."                       },
    { from: "2047", to: "[P₂₀₄₇] — random → learned" },
  ]}
/>

Every position has its own learnable vector. Engineers decide the shape (e.g. `2048 × 768`) — training learns the values.

## Combining Both Embeddings

GPT adds the token embedding and position embedding together — enriching the token's meaning with its position.

The word keeps its meaning — but now also knows **where it appears** in the sentence.

## Key Takeaways

- Position IDs are simple integers generated in order.
- GPT converts Position IDs into vectors via the Positional Embedding Matrix.
- The matrix is randomly initialized and learned during training.
- Token and positional embeddings are **added** together.
- The final vector carries both meaning and position before entering the Transformer.
