> *"Before a token can understand other tokens, it must first know what it is looking for, how others describe themselves, and what information they can share."*

## Quick Recap

In the previous lesson, we discovered that embeddings are **fixed representations** — they capture general meaning but cannot determine meaning in a specific sentence.

To solve this, researchers introduced **Self-Attention**. But another question immediately appears:

> **How does a token know which other tokens are important?**

---

## The Problem

Imagine you walk into a library. Thousands of books surround you. You want to learn about `Artificial Intelligence`.

Can you read every single book? No. Instead, you search for the most relevant ones.

Language works the same way. When a token wants to understand itself, it shouldn't treat every other token equally — it needs a way to decide **who is worth paying attention to**.

## Intuition

Imagine a classroom. The teacher asks: **"Who knows Python?"**

Every student reacts differently — some raise their hands, others stay silent. The teacher naturally pays attention to the relevant students.

Tokens behave the same way. Every token decides **who is most useful** before learning from them.

---

## Why Isn't One Embedding Enough?

Currently every token has one embedding vector. That single vector is being asked to:

- Search for information (asking questions)
- Describe itself to others (answering questions)
- Share its actual knowledge

One vector doing three jobs creates unnecessary limitations. Researchers decided to split these responsibilities.

## A Simple Example

Consider the sentence: `The cat drinks milk.`

Focus on the token `drinks`:

<FlowDiagram title="Token 'drinks' Creates Three Vectors" steps={[
  "Token: 'drinks'",
  "Query: 'Who performs this action?'",
  "Key:   'I represent an action (drinking)'",
  "Value: 'I can contribute information about the action'"
]} />

The token `cat` creates its own Key — describing itself as the subject. If the Query from `drinks` and the Key from `cat` match well, the Value from `cat` will be used.

No information is copied yet — we're only **preparing** the three representations.

## Key Takeaways

- One embedding cannot efficiently perform every role.
- Self-Attention separates responsibilities into Query, Key, and Value.
- Query asks what information is needed.
- Key describes what a token represents.
- Value contains the information that can be shared.
- Every token creates its own Query, Key, and Value vectors.

## What's Next?

Now we understand **why** Query, Key, and Value exist.

The next question is even more interesting.

> **How does GPT actually create these three vectors from a single embedding?**

We'll discover that every embedding is multiplied by three different learnable weight matrices — **WQ**, **WK**, and **WV**.

This is where the mathematics of Self-Attention truly begins.
