> *"Adding more layers should make a model better. For a long time, it made them worse."*

---

## The Problem

GPT doesn't use one Transformer block — it stacks dozens.

<FlowDiagram title="Stacked Transformer Blocks" steps={[
  "Input",
  "Block 1",
  "Block 2",
  "Block 3",
  "...",
  "Block 48",
  "Output"
]} />

A natural question: if one block helps, shouldn't more blocks always help?

**Surprisingly, no.** Researchers discovered that after a certain depth, optimization became much harder.

## 1. Information Degradation

Block 1 produces a useful representation. Every additional block modifies it — and with enough transformations, useful information gradually becomes hard to preserve.

<FlowDiagram title="Information Degradation Over Layers" steps={[
  "Input → Block 1 → Useful Representation",
  "Block 2 → Transforms it",
  "Block 3 → Transforms it again",
  "Block N → Original signal diluted"
]} />

---

## 2. Vanishing Gradients

During training, gradients travel backward through all layers.

<TokenMapping
  title="Gradient Magnitude Across Layers"
  fromLabel="Layer"
  toLabel="Gradient"
  items={[
    { from: "Layer 48 (output)", to: "1.000" },
    { from: "Layer 40",          to: "0.512" },
    { from: "Layer 30",          to: "0.134" },
    { from: "Layer 20",          to: "0.021" },
    { from: "Layer 10",          to: "0.003" },
    { from: "Layer 1 (early)",   to: "≈ 0.000 — learns nothing" },
  ]}
/>

As gradients pass through many layers, they become exponentially smaller. Early layers receive almost no learning signal — the **Vanishing Gradient Problem**.

---

## 3. Identity Mapping Problem

If one block has already learned a perfect representation, the next block should ideally leave it unchanged.

<Comparison
  title="What We Want vs What Happens"
  left={{
    label: "Ideal Behaviour",
    points: [
      "Block adds useful refinement",
      "If nothing to learn: pass input through unchanged",
      "Output ≈ Input when no improvement needed",
    ]
  }}
  right={{
    label: "Reality Without Residuals",
    points: [
      "Block must learn to copy its own input",
      "Learning 'do nothing' is surprisingly hard",
      "Each new block risks destroying previous work",
    ]
  }}
/>

## The Key Insight

Researchers asked a simple question:

Instead of forcing every block to completely replace its input, **why not let it learn only the change?**

<Comparison
  title="Replace vs Refine"
  left={{
    label: "Without Residuals",
    points: [
      "Output = F(x)",
      "Block must learn the full representation",
      "Original input is replaced",
      "Hard to train at depth",
    ]
  }}
  right={{
    label: "With Residuals",
    points: [
      "Output = x + F(x)",
      "Block only learns the improvement",
      "Original input is preserved",
      "Easy to train even at depth 48+",
    ]
  }}
/>

## Why Addition Works

Suppose `x = [2, 5]` and the block computes `F(x) = [-1, 2]`.

<TokenMapping
  title="With vs Without Residuals"
  fromLabel="Method"
  toLabel="Output"
  items={[
    { from: "Without residuals: F(x)",       to: "[-1, 2]  — original lost"        },
    { from: "With residuals: x + F(x)",      to: "[1, 7]  — refined, not replaced" },
  ]}
/>

The model keeps the previous representation while the block adds useful improvements.

---

## Mathematics

<MathBlock title="Residual Connection">
  $$\text{Output} = x + F(x)$$
</MathBlock>

where **x** is the original input and **F(x)** is the transformation learned by the Transformer block.

---

## Key Takeaways

- Stacking Transformer blocks introduces three problems: information degradation, vanishing gradients, and identity mapping.
- Residual connections solve all three by preserving the input.
- Every block learns a **modification** `F(x)`, not a complete replacement.
- The fundamental equation: `Output = x + F(x)`.
