## Part 3 — Token Embeddings

Each integer ID is looked up in the **Embedding Matrix** — a learned table of shape `[vocab_size × d_model]`. The row at index 42 is the embedding vector for "I". The row at index 381 is the embedding vector for "love".

<FlowDiagram title="Token ID → Dense Vector" steps={[

  'Token ID: 381',
  'Embedding lookup — row 381 of the embedding matrix',
  'Dense vector ∈ ℝ⁷⁶⁸',
]} />

After this step, both tokens exist as 768-dimensional vectors. These vectors were learned during pre-training — tokens that appear in similar contexts end up with similar vectors.

The embedding matrix has shape `[50,000 × 768]`. Every forward pass through the model is free to look up any row. Only the rows corresponding to the input tokens are used.

## Part 4 — Positional Information

Self-attention has no built-in sense of order. Without positional information, "I love" and "love I" would produce identical representations — a serious problem for language.

The solution: add a position vector to each token embedding before any computation begins.

  'x⁽⁰⁾ = e⁽⁰⁾ + p⁽⁰⁾',
  'Token embedding for "love" →  e⁽¹⁾  ∈ ℝ⁷⁶⁸',
  'Positional vector for pos 1 →  p⁽¹⁾  ∈ ℝ⁷⁶⁸',
  'x⁽¹⁾ = e⁽¹⁾ + p⁽¹⁾',
]} />

## Part 5 — Q, K, V Projections

The first thing every Transformer block does is project each token's representation into three separate vectors: **Query**, **Key**, and **Value**.

<FlowDiagram title="One Token → Three Projections" steps={[
  'Input vector x ∈ ℝ⁷⁶⁸',
  'Q = x Wᴼ   (What am I looking for?)',
  'K = x Wᴷ   (What do I contain?)',
  'V = x Wᵛ   (What should I pass forward?)',
]} />

<TokenMapping
  title="The Role of Each Projection"
  fromLabel="Vector"
  toLabel="Intuition"
  items={[
    { from: 'Query (Q)', to: '"I am looking for tokens that relate to me in this way"' },
    { from: 'Key   (K)', to: '"Here is what I advertise about myself"' },
    { from: 'Value (V)', to: '"If you attend to me, here is what you actually receive"' },
  ]}
/>

Each weight matrix (`Wᴼ`, `Wᴷ`, `Wᵛ`) has shape `[768 × 64]` in a single head of GPT-2 Small. The projection is a standard matrix multiplication — learned during training.

For the full sequence of 2 tokens:

```
X      ∈ ℝ^{2 × 768}
Wᴼ    ∈ ℝ^{768 × 64}
──────────────────────
Q = X Wᴼ  ∈ ℝ^{2 × 64}
K = X Wᴷ  ∈ ℝ^{2 × 64}
V = X Wᵛ  ∈ ℝ^{2 × 64}
```

All three are computed in parallel. No sequential dependency between them.

<div id="phase-scores" data-phase="phase-scores" />

## Part 6 — Attention Scores

Queries and Keys are used to compute how much each token should attend to every other token.

The operation is a **scaled dot product**: multiply the query matrix by the transposed key matrix, then divide by √dₖ.

<MathBlock title="Attention Score Computation">
  $$\text{Scores} = \frac{QK^{\top}}{\sqrt{d_k}}$$
</MathBlock>

For the sequence "I love":

<AttentionMatrix
  title="Raw Scaled Attention Scores (Illustrative)"
  queryLabel="Query token"
  keyLabel="Key token"
  columns={['"I"', '"love"']}
  rows={[
    { label: '"I"',    values: ['2.0', '5.0'] },
    { label: '"love"', values: ['1.0', '3.0'] },
  ]}
  caption="Each cell is the dot product of one query vector with one key vector, divided by √64 = 8."
/>

Reading this matrix: the query for "I" scores 2.0 against the key for "I" itself, and 5.0 against the key for "love". A higher score means stronger relevance.

The division by √dₖ (√64 = 8) prevents the dot products from becoming very large and saturating the softmax that follows.

<div id="phase-mask" data-phase="phase-mask" />

## Part 7 — Causal Masking

GPT is an **autoregressive** model. During training it processes the entire sequence at once, but each position must only be allowed to attend to itself and earlier positions — never future ones.

The causal mask sets all future-position scores to −∞ before softmax. Because e^(−∞) = 0, those positions receive exactly zero attention weight after softmax.

<CausalMaskVisualizer />

Toggle between the three views above:

- **Without mask** — every token can see every other token, including the future. This leaks information that would not exist at generation time.
- **Causal mask applied** — upper-triangle entries are replaced with −∞.
- **After softmax** — future positions receive 0% attention weight. Each row still sums to 100%.

This is what makes training and generation consistent: the model never sees information it would not have during autoregressive prediction.

<div id="phase-values" data-phase="phase-values" />

## Part 9 — Weighted Values

The attention weights are used to compute a **weighted sum of the Value vectors**.

<MathBlock title="Attention Output">
  $$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right) V$$
</MathBlock>

For each token, the output is a mixture of all allowed Value vectors, weighted by how much attention was paid to each position.

<WeightedSumVisualizer />

The output of this operation is a new matrix with the same shape as Q, K, V: `[2 × 64]`. Each row is a contextually-informed representation of one token — not just its isolated embedding, but a blend of information gathered from the sequence.

---

<div id="phase-multihead" data-phase="phase-multihead" />

## Part 10 — Multi-Head Attention

One set of Q, K, V captures one kind of relationship. GPT-2 Small uses **12 attention heads** running in parallel.

Each head has its own weight matrices and therefore learns different relationships:

<MultiHeadArchitecture />

After all heads run independently, their outputs are concatenated and projected through an output matrix Wᴼ:

```
[head₁ output ‖ head₂ output ‖ ... ‖ head₁₂ output]
     ↓
  Concatenated: [2 × 768]   (12 heads × 64 dims = 768)
     ↓
  × Wᴼ  ∈ ℝ^{768 × 768}
     ↓
  Multi-Head Attention output: [2 × 768]
```

The shape returns to `[2 × 768]` — same as the input. This is critical: every sublayer in the Transformer is **shape-preserving**, which is what allows arbitrary stacking.

## Part 11 — First Residual Connection

The attention output is not used to replace the input. It is **added** to the input.

<MathBlock title="Residual Connection">
  $$x_2 = x + \text{Attention}(x)$$
</MathBlock>

<Comparison
  title="What the Residual Connection Guarantees"
  left={{
    label: 'Without Residual',
    accent: 'var(--color-error)',
    points: [
      'The original representation is overwritten',
      'Gradients must pass through every layer sequentially',
      'Early layers receive tiny gradients — stop learning',
      'Deep models become practically untrainable',
    ],
  }}
  right={{
    label: 'With Residual (x + F(x))',
    accent: 'var(--color-success)',
    points: [
      'Original representation is preserved alongside the update',
      'Gradient highway: ∂y/∂x = 1 + ∂F(x)/∂x',
      'The +1 keeps gradients strong all the way to layer 1',
      'GPT-3 has 96 blocks — residuals make this trainable',
    ],
  }}
/>

Every Transformer block has **two** residual connections — one around attention, one around the FFN. The block learns what to *add*, not what to *replace*.

## Part 12 — Layer Normalization

After the residual addition, the representation may have grown to an extreme scale through accumulated additions across many layers. Layer Normalization brings it back to a stable, predictable range.

<FlowDiagram title="Pre-LayerNorm (Modern GPT)" steps={[
  'Input x₂  (may have large or small values)',
  'Compute mean μ across 768 dimensions',
  'Compute variance σ² across 768 dimensions',
  'Normalize: x̂ = (x₂ − μ) / √(σ² + ε)',
  'Scale: × γ  (learned per-dimension)',
  'Shift: + β  (learned per-dimension)',
  'Stable output — ready for the FFN',
]} />

<TokenMapping
  title="LayerNorm at a Glance"
  fromLabel="Step"
  toLabel="What it does"
  items={[
    { from: 'Normalize',   to: 'Mean ≈ 0, variance ≈ 1 — removes runaway scale' },
    { from: '× γ',         to: '768 learned scale knobs — restores useful spread' },
    { from: '+ β',         to: '768 learned shift knobs — restores useful center' },
    { from: 'Final output', to: 'Not necessarily mean=0 — γ and β move it freely' },
  ]}
/>

In modern GPT (Pre-LN), LayerNorm is applied **before** the sublayer, so the residual path remains a clean identity: `y = x + F(LayerNorm(x))`.

## Part 13 — Feed-Forward Network

After attention has mixed information *between* tokens, the FFN transforms each token's representation *independently*.

```
Each token's vector:  [1 × 768]
      ↓
Linear expansion:     [1 × 3072]   (× 4 expansion factor)
      ↓
GELU activation:      [1 × 3072]   (non-linearity)
      ↓
Linear compression:   [1 × 768]    (back to model dimension)
```

<FFNPipelineVisualizer />

The FFN is applied to each token's row independently — it does not mix information between positions. Its role is to transform the representation that attention assembled: adding non-linearity, learning feature interactions, and expanding the model's representational capacity.

<Comparison
  title="Attention vs FFN — Their Different Jobs"
  left={{

## Part 14 — Second Residual + LayerNorm

The FFN output is added back to the input of the FFN (second residual connection), then normalized again:

<MathBlock title="Second Residual + Norm">
  $$x_3 = x_2 + \text{FFN}(\text{LayerNorm}(x_2))$$
</MathBlock>

<FlowDiagram title="Complete Transformer Block — Pre-LN" steps={[
  'Input x',
  'LayerNorm₁(x)',
  'Multi-Head Attention → A',
  'x₂ = x + A   ← first residual',
  'LayerNorm₂(x₂)',
  'FFN → F',
  'x₃ = x₂ + F  ← second residual',
  'Output x₃   [same shape: 2 × 768]',
]} />

The output shape `[2 × 768]` is identical to the input shape. This is what makes it possible to stack N identical-architecture blocks — each block's output is a valid input for the next.

## Part 16 — Final Hidden State

After all N blocks, the final output is called the **final hidden state**: a matrix `[T × 768]` where each row is a contextually-enriched representation of one token.

For next-token prediction, only one row matters: the **last token's row**. This is the vector that has attended to everything before it and synthesized the full context into a single 768-dimensional representation.

## Part 17 — Output Projection

The final hidden state vector `h ∈ ℝ⁷⁶⁸` is multiplied by the output projection matrix to produce one score for every token in the vocabulary.

<MathBlock title="Output Projection">
  $$z = h \cdot W_{\text{out}} \quad [1 \times 768] \cdot [768 \times 50{,}000] = [1 \times 50{,}000]$$
</MathBlock>

<OutputProjectionVisualizer />

The output projection matrix `W_out ∈ ℝ^{768 × 50,000}` is a learned linear classifier. Each column is a 768-dimensional vector representing one vocabulary token. The dot product between the hidden state and a column gives the **raw compatibility score** (logit) for that token.

The inner dimension 768 cancels, producing a vector of 50,000 raw scores — one per word in the vocabulary.

## Part 19 — Softmax → Probabilities

Softmax converts the raw logits into a valid probability distribution.

<MathBlock title="Softmax">
  $$P(w_i) = \frac{e^{z_i}}{\displaystyle\sum_{j=1}^{V} e^{z_j}}$$
</MathBlock>

<VocabularyLogitsVisualizer />

Use the sliders above to adjust individual logit values and watch how the probability distribution responds. Key observations:

- All probabilities are in `[0, 1]`
- All probabilities sum to exactly 1.0
- A large logit difference (e.g. 12 vs 2) produces a very concentrated distribution
- A small logit difference (e.g. 4 vs 3) produces a more spread-out distribution

<div id="phase-decoding" data-phase="phase-decoding" />

## Part 20 — Decoding Strategy

Having a probability distribution is not the same as having chosen the next token. Something must **select** one token from the distribution.

<DecodingStrategiesVisualizer defaultTab="greedy" />

The four main strategies:

- **Greedy** — always pick the highest-probability token. Deterministic, fast, can be repetitive.
- **Temperature** — scale the logits by 1/T before softmax. Low T sharpens the distribution; high T flattens it.
- **Top-K** — discard all but the K highest-probability tokens, then sample from the renormalized remainder.
- **Top-P (Nucleus)** — keep the smallest set of tokens whose cumulative probability reaches P, then sample from them.

Each strategy makes a different trade-off between predictability, diversity, and quality. In practice, most production systems combine Temperature + Top-P.
