# The Problem

Transformers are deep. GPT-3 has 96 layers. GPT-4 is estimated to have even more. Every Transformer block performs Multi-Head Attention, adds a residual connection, runs a Feed-Forward Network, and adds another residual connection.

At each step, vectors are transformed, combined, and passed forward. With enough layers, the values inside those vectors can drift — some dimensions grow very large, others shrink toward zero, and the overall scale becomes unpredictable.

This is not a theoretical concern. It is something researchers observed while training early deep networks, and it is the problem LayerNorm was designed to address.

# Why Are Extreme Values a Problem?

Think of it as a factory floor analogy.

You have machines that are calibrated to receive inputs roughly between −2 and +2. They function well in that range — their internal computations stay numerically stable, their outputs are predictable, and adjustments during calibration (training) are precise.

Now apply this to a Transformer. Every sublayer is a kind of machine. If its input has drifted to extreme scale, computation becomes less stable and training becomes less reliable.

# The Communication Analogy

Here is another way to feel this intuitively.

Imagine a conversation at normal volume. Both speakers hear each other clearly. Information flows without friction.

Now imagine the same conversation, but one person alternates between whispering and shouting unpredictably. The words are still there — the information is technically present — but communication has become much harder.

Neural network activations work the same way. The representations carry information regardless of scale. But when activations are wildly inconsistent in magnitude — sometimes very small, sometimes very large — the downstream computations that consume them become less stable.

**The information still exists. The problem is consistency of scale.**

---

# The Question LayerNorm Asks

Layer Normalization asks one simple question before passing a token's representation to the next computation:

> *"Can I bring these values to a stable, consistent scale — without destroying the relative structure they encode?"*

The answer is yes. And the mechanism is straightforward.

---

# What Exactly Is Being Normalized?

This is a critical point.

LayerNorm normalizes **across the hidden dimensions of a single token**.

For a token with a 768-dimensional representation, LayerNorm computes the mean and variance of those 768 numbers and normalizes accordingly. It does this independently for each token — it does not mix information across the batch or across positions.

<TokenMapping
  title="What LayerNorm Operates On"
  fromLabel="Scope"
  toLabel="What Is Normalized"
  items={[
    { from: "One token, all 768 dims",  to: "← LayerNorm normalizes this"  },
    { from: "All tokens, one dim",      to: "← BatchNorm normalizes this"  },
    { from: "Across positions",         to: "← LayerNorm does NOT do this" },
    { from: "Across the batch",         to: "← LayerNorm does NOT do this" },
  ]}
/>

Every token is treated independently. The normalization is computed fresh for each token from its own hidden dimensions.

---

# Step 1 — Compute the Mean

Take a simple example. A token has four hidden dimensions:

$$x = [2,\ 4,\ 6,\ 8]$$

The mean is:

<MathBlock title="Step 1 — Mean">
  $$\mu = \frac{1}{d} \sum_{i=1}^{d} x_i = \frac{2+4+6+8}{4} = 5$$
</MathBlock>

where **d** is the number of hidden dimensions and **μ** is the mean across those dimensions.

---

# Step 2 — Subtract the Mean

Center the values around zero:

<MathBlock title="Step 2 — Center">
  $$x - \mu = [2-5,\ 4-5,\ 6-5,\ 8-5] = [-3,\ -1,\ 1,\ 3]$$
</MathBlock>

The representation is now centered at zero. The relative structure is preserved — the differences between values are exactly the same as before. The smallest value is still the smallest. The largest is still the largest.

---

# Step 3 — Compute the Standard Deviation

Measure how spread out the values are:

<MathBlock title="Step 3 — Standard Deviation">
  $$\sigma = \sqrt{\frac{1}{d}\sum_{i=1}^{d}(x_i - \mu)^2} = \sqrt{\frac{9+1+1+9}{4}} = \sqrt{5} \approx 2.24$$
</MathBlock>

---

# Step 4 — Divide by the Standard Deviation

Scale the centered values so they have unit variance:

<MathBlock title="Step 4 — Normalize">
  $$\hat{x} = \frac{x - \mu}{\sigma} \approx \frac{[-3,\ -1,\ 1,\ 3]}{2.24} \approx [-1.34,\ -0.45,\ 0.45,\ 1.34]$$
</MathBlock>

The normalized representation has approximately mean = 0 and variance = 1.

<TokenMapping
  title="Normalization Step by Step"
  fromLabel="After Step"
  toLabel="Values"
  items={[
    { from: "Original x",             to: "[2, 4, 6, 8]"                    },
    { from: "Subtract mean (μ = 5)",  to: "[-3, -1, 1, 3]"                  },
    { from: "Divide by σ (≈ 2.24)",   to: "[-1.34, -0.45, 0.45, 1.34]"      },
    { from: "Final: mean ≈ 0, var ≈ 1", to: "✓ Stable scale"                },
  ]}
/>

---

# The Core Formula

Putting it all together, the normalization formula is:

<MathBlock title="LayerNorm — Normalization Step">
  $$\hat{x}_i = \frac{x_i - \mu}{\sqrt{\sigma^2 + \varepsilon}}$$
</MathBlock>

Where:
- **x_i** is the i-th value in the token's hidden representation
- **μ** is the mean across all hidden dimensions for this token
- **σ²** is the variance across all hidden dimensions for this token
- **ε** (epsilon) is a tiny constant (e.g. 1e-5) added for numerical safety — it prevents division by zero if the variance happens to be exactly zero
- **x̂_i** is the normalized output

# Did We Lose the Meaning?

This is a fair concern. If we rescale everything, do we lose the information that was encoded in those large values?

The answer requires careful thought.

The **absolute scale** of the values before normalization carries some information — specifically, it tells us about the magnitude of what came before. After normalization, that absolute scale is removed.

But what remains is the **relative structure**: which dimensions are high relative to others, which are low, how they relate. For most of what a Transformer needs to compute in the next layer, this relative structure is what matters.

The model learns to encode information in the shape of the representation, not just in its raw magnitude.

<KeyInsight title="What Normalization Preserves">
Normalization standardizes the scale while preserving the relative structure of the representation. The downstream computations care mostly about how dimensions relate to each other — not about the absolute magnitude. That is what makes normalization effective without being destructive.
</KeyInsight>

---

# But Researchers Found Another Problem

After normalization, every token's representation has approximately mean = 0 and variance = 1.

This is stable. But it is also **rigid**.

The model might have learned — through thousands of training steps — that for a certain type of token, the useful representation should have a larger spread, or be centered slightly above zero. Forcing every token's representation to exactly mean = 0, variance = 1 before every computation removes that flexibility.

**Normalization alone is too restrictive.** The model cannot express that it prefers a different scale for different contexts.

---

# Introducing γ and β

The solution is to let the model learn to adjust the scale and center after normalization.

Two learnable parameters are introduced:

- **γ (gamma)** — a scale parameter
- **β (beta)** — a shift parameter

Together they form an **affine transformation** applied after normalization:

<MathBlock title="Full LayerNorm — With Learnable Parameters">
  $$y_i = \gamma_i \cdot \hat{x}_i + \beta_i$$
</MathBlock>

Or written out in full:

<MathBlock title="LayerNorm — Complete Formula">
  $$y_i = \gamma_i \cdot \frac{x_i - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \beta_i$$
</MathBlock>

Where **y_i** is the final LayerNorm output for dimension i.

---

# Why Do We Need the Scale Knob?

Suppose after normalization a token's representation is:

$$\hat{x} = [-1,\ 0,\ 1]$$

With γ = 1 and β = 0, the output is unchanged:

$$y = 1 \times [-1,\ 0,\ 1] + 0 = [-1,\ 0,\ 1]$$

During training, the model discovers through gradient descent that a larger spread is more useful for the downstream computation. The optimizer updates γ toward 2:

$$y = 2 \times [-1,\ 0,\ 1] + 0 = [-2,\ 0,\ 2]$$

The scale knob lets the model restore a spread it finds useful — but now it is a *learned and controlled* spread, not a runaway drift from 30 layers of accumulated additions.

---

# Why Do We Need β?

Suppose the model finds it useful for the representation to be centered around 3 rather than 0. With β = 3:

$$y = 2 \times [-1,\ 0,\ 1] + 3 = [1,\ 3,\ 5]$$

The β parameter lets the model shift the center of the representation to wherever it learns is most useful.

# Important: LayerNorm Does NOT Force the Final Output to Mean 0 and Variance 1

This is a common misconception worth addressing directly.

The **normalization step** produces x̂ with approximately mean = 0 and variance = 1.

But γ and β immediately transform x̂ into the final output **y**. If γ ≠ 1 or β ≠ 0, the output y will generally have a different mean and variance.

<KeyInsight title="The Final LayerNorm Output">
LayerNorm normalizes first, then applies a learned affine transformation. The final output does NOT necessarily have mean = 0 or variance = 1. The model learns the mean and scale it actually needs through γ and β.
</KeyInsight>

---

# γ and β Are Learned Parameters

Where do γ and β come from? They are trainable parameters, just like the weight matrices in Attention and the FFN.

At initialization:

$$\gamma = 1, \quad \beta = 0$$

This means LayerNorm starts as pure normalization — the identity affine transformation leaves x̂ unchanged. As training proceeds, the optimizer updates γ and β alongside all the other parameters:

<FlowDiagram title="How γ and β Are Learned" steps={[
  "Initialize: γ = 1, β = 0",
  "Forward pass → compute output y",
  "Compute loss",
  "Backpropagation → compute gradients ∂L/∂γ and ∂L/∂β",
  "Gradient descent → update γ and β",
  "Repeat until γ and β encode useful scale and shift"
]} />

---

# Gradient Descent Doesn't Decide γ = 2 by Itself

Here is an important subtlety.

When we said "the model learns γ = 2", we did not mean that gradient descent looks at the task and decides "I need a scale of 2." It has no such awareness.

What happens is simpler and more mechanical:

The optimizer observes that increasing γ slightly reduces the loss. It does so. Over thousands of steps, γ drifts toward whatever value consistently produces better predictions. The final value of γ = 2 (or whatever it becomes) is simply the value that was most useful for the task, discovered through pure optimization.

<Tip title="Optimization, Not Reasoning">
The model does not reason about what γ should be. It just follows gradients. The useful values of γ and β emerge from millions of parameter updates, not from any explicit decision.
</Tip>

---

# γ and β Are Not Single Numbers

In a real Transformer, γ and β are not scalars. They are **vectors**.

If the hidden dimension is 768, then:

$$\gamma = [\gamma_1,\ \gamma_2,\ \ldots,\ \gamma_{768}]$$
$$\beta = [\beta_1,\ \beta_2,\ \ldots,\ \beta_{768}]$$

Each hidden dimension gets its own independent scale and shift.

<TokenMapping

/>

This means the LayerNorm in one Transformer block with d = 768 has 768 + 768 = **1,536 learnable parameters** just for γ and β.

---

# Think of γ and β as 768 Pairs of Knobs

Each pair of knobs controls one dimension of the representation:

- the first knob (γ) says how spread out that dimension should be
- the second knob (β) says where that dimension should be centered

The model learns all 768 pairs simultaneously through training. Some dimensions may end up with γ close to 1 and β close to 0 — meaning normalization was already optimal for them. Others may end up with very different values.

# Full LayerNorm Pipeline

Here is the complete computation from input to output:

<FlowDiagram title="LayerNorm — Complete Pipeline" steps={[
  "Input x  (token's hidden representation)",
  "Compute mean μ across all d dimensions",
  "Compute variance σ² across all d dimensions",
  "Normalize:  x̂ = (x − μ) / √(σ² + ε)",
  "Scale:      x̂ × γ",
  "Shift:      + β",
  "Output y  (stable, learned-scale representation)"
]} />

All of this happens independently for **every token** at **every LayerNorm** in the network. A single forward pass through GPT-3 involves 96 blocks × 2 LayerNorms per block = **192 independent LayerNorm computations** per token.

# Why LayerNorm Works Well With Residual Connections

In Day 25 we learned about residual connections: `y = x + F(x)`.

It is worth comparing the two mechanisms side by side, because they are complementary — not competing.

# Post-LayerNorm

The original Transformer paper (Vaswani et al., 2017) placed LayerNorm **after** the residual addition. This is called **Post-LayerNorm** (Post-LN):

<MathBlock title="Post-LayerNorm">
  $$y = \operatorname{LayerNorm}(x + F(x))$$
</MathBlock>

<FlowDiagram title="Post-LayerNorm Architecture" steps={[
  "Input x",
  "Sublayer computation F(x)  ← Attention or FFN",
  "Residual addition:  x + F(x)",
  "LayerNorm( x + F(x) )",
  "Output → next sublayer"
]} />

In Post-LN, normalization happens **after** the residual addition. The sum `x + F(x)` is normalized before being passed forward.

---

# The Gradient-Flow Problem

Post-LN has a subtle issue with gradient flow in very deep networks.

During backpropagation, the gradient must travel backward through the LayerNorm operation. LayerNorm is differentiable — it does not destroy gradients. But it does add another transformation into the backward path.

In very deep networks (96+ layers), stacking many Post-LN blocks means the gradient accumulates these transformations. Researchers observed that this made very deep Post-LN Transformers harder to train — they often required careful warm-up schedules and were more sensitive to hyperparameters.

<Warning title="Post-LN Is Not Broken — It Is Harder to Scale">
Post-LN works well for shallow and moderate-depth Transformers. The challenge appears specifically in very deep networks where gradient flow across many layers becomes more delicate.
</Warning>

---

# Pre-LayerNorm

Modern GPT-style Transformers use a different placement: **Pre-LayerNorm** (Pre-LN), where normalization happens **before** the sublayer computation:

<MathBlock title="Pre-LayerNorm">
  $$y = x + F(\operatorname{LayerNorm}(x))$$
</MathBlock>

<FlowDiagram title="Pre-LayerNorm Architecture (Modern GPT)" steps={[
  "Input x",
  "LayerNorm(x)  ← normalize before computing",
  "Sublayer computation F( LayerNorm(x) )  ← Attention or FFN",
  "Residual addition:  x + F( LayerNorm(x) )",
  "Output → next sublayer"
]} />

In Pre-LN, the original `x` travels through the residual path **completely untouched**. The transformation branch receives a normalized version of x, but the identity path from the residual addition is clean.

In Post-LN, every gradient traveling backward through the residual highway must pass through LayerNorm after the merge point.

In Pre-LN, the residual addition happens **after** the transformation. The identity path `x` flows directly to the addition node — clean and unmodified. The gradient traveling back through the identity path does not encounter LayerNorm at all.

# Why Did Researchers Move Toward Pre-LN?

As Transformers grew deeper, the training dynamics of Post-LN became more fragile. Models required:

- careful learning rate warm-up schedules
- more conservative hyperparameter tuning
- greater sensitivity to initialization

Pre-LN models were observed to be more stable during early training, tolerate higher learning rates, and require less careful warm-up. For very deep models — GPT-2 (48 layers), GPT-3 (96 layers) — this stability difference became meaningful in practice.

<Tip title="Pre-LN Is the Practical Choice for Deep Models">
Pre-LN does not theoretically prevent all training instability. It reduces the sensitivity of gradient flow in very deep stacks, making the training process more robust. For models with tens to hundreds of layers, this matters significantly.
</Tip>

# A Deeper Insight

Think about what the Transformer block is actually learning to do.

With residual connections, the block does not replace its input — it **adds an update** to it:

$$\text{output} = \underbrace{x}_{\text{original}} + \underbrace{F(\operatorname{LayerNorm}(x))}_{\text{learned update}}$$

The model is not saying "here is a completely new representation." It is saying "here is the original representation, refined by what I learned to add to it."

LayerNorm ensures that the input to F is always stably scaled before computing the update. The residual ensures the original information survives alongside the update.

<KeyInsight title="The Block as a Refinement Machine">
Every Transformer block learns an update to the current representation — not a replacement. The residual connection preserves what was already known. LayerNorm ensures the update is computed from a stable, well-scaled input. Together they make each block an incremental refinement rather than a destructive transformation.
</KeyInsight>

# One More Important Realization

LayerNorm is **differentiable**. Gradients flow through it during backpropagation. It does not break the backward pass — it is simply another differentiable function in the computation graph, like the linear layers or the activation functions.

This means the gradient of the loss can flow backward through LayerNorm and update γ and β, just as it updates weight matrices elsewhere. LayerNorm participates fully in the learning process.

What LayerNorm does **not** do is completely eliminate the possibility of unstable training. It improves numerical stability and makes optimization more tractable. Combined with residual connections, careful initialization, and the right optimizer, it supports the training of networks that would otherwise be practically impossible to train.

# Key Takeaways

- Activations in deep Transformers can drift to extreme scales through accumulated residual additions.
- LayerNorm normalizes each token's representation **across its own hidden dimensions** — independently of other tokens and the batch.
- Normalization brings the representation to approximately mean = 0 and variance = 1.
- The core formula is: x̂ = (x − μ) / √(σ² + ε)
- Normalization alone is too rigid — it forces a fixed scale and center regardless of what the model has learned to prefer.
- Learnable γ and β (scale and shift vectors) restore representational flexibility after normalization.
- γ and β are vectors of size d — each hidden dimension gets its own independent pair of parameters.
- The final LayerNorm output does NOT necessarily have mean = 0 or variance = 1.
- γ and β start at 1 and 0 respectively, then evolve through gradient descent during training.
- Post-LN (original Transformer) places LayerNorm after the residual addition: `y = LN(x + F(x))`.
- Pre-LN (modern GPT) places LayerNorm before the sublayer: `y = x + F(LN(x))`.
- Pre-LN provides a cleaner gradient path through the residual highway, supporting more reliable training of very deep models.
- Residual connections and LayerNorm solve different problems and are both necessary in a complete Transformer block.

## Questions That Changed My Understanding

**Q: Does LayerNorm normalize across tokens or within a token?**

Within a single token — across its hidden dimensions. Each token is normalized independently. LayerNorm has no knowledge of other tokens in the sequence or other examples in the batch.

**Q: If normalization removes scale information, doesn't the model lose something?**

The absolute scale is removed, but the relative structure — which dimensions are high or low relative to each other — is preserved. The model encodes meaning in the shape of the representation. For the computations that follow (Attention, FFN), relative structure is what matters. Absolute magnitude would just be noise from accumulated additions.

**Q: Why do γ and β need to be per-dimension? Why not just one γ and one β?**

Different hidden dimensions encode qualitatively different kinds of information. The model may need dimension 42 at a different scale than dimension 317. A single global γ would force all dimensions to the same spread, which is almost as rigid as pure normalization. Per-dimension parameters give the model the granularity it needs.

**Q: Pre-LN keeps the residual path clean — but doesn't that mean the input to F(x) is always normalized, even when that's not ideal?**

Yes — in Pre-LN, every sublayer always receives a normalized input. This is a deliberate trade: you give up the ability to pass non-normalized signal into F(x) in exchange for cleaner gradient flow through the identity path. In practice, the γ and β parameters inside LayerNorm give the model enough flexibility to compensate, and the training stability benefits outweigh the constraint.

**Q: Is LayerNorm the only way to normalize? What about BatchNorm?**

BatchNorm normalizes across the batch dimension — it uses statistics computed over multiple training examples. This works well in computer vision where batch sizes are large and inputs are images. For language, batches have variable lengths and the sequence position matters — per-example normalization (LayerNorm) is a much better fit. LayerNorm became the standard for Transformers precisely because it does not depend on batch statistics.
