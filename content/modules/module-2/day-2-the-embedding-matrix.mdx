## What is Vectorization?

In the previous lesson, we learned that Token IDs cannot carry meaning.

Before GPT can perform any mathematical computation, it must convert Token IDs into dense numerical vectors.

This process is called **Vectorization**, and it is performed by the **Embedding Layer**.

<FlowDiagram title="Vectorization Pipeline" steps={[
  "Input Text",
  "Tokenizer",
  "Token IDs",
  "Vectorization (Embedding Lookup)",
  "Embedding Vectors",
  "Transformer"
]} />

> Vectorization converts symbolic Token IDs into dense numerical vectors using the learned Embedding Matrix.

---

## The Problem

Suppose the tokenizer produces `Cat → Token ID = 205`.

We know GPT converts it into `[0.42, -0.81, 1.24, ...]`.

But where did these numbers come from?

Did OpenAI engineers manually write them?

Did someone create a giant dictionary containing every word and its meaning?

**No.**

---

## Intuition

Imagine opening a brand new notebook. Every page is completely blank.

As you continue learning, you gradually fill each page with useful information.

The Embedding Matrix works in a very similar way — initially every row contains meaningless random numbers. Training slowly transforms them into meaningful representations.

## Deep Explanation

GPT stores all embedding vectors inside one large table — the **Embedding Matrix**.

Each row represents one token. Whenever GPT receives a Token ID, it retrieves the corresponding row from this table.

<FlowDiagram title="Embedding Lookup" steps={[
  "Token ID: 205",
  "Embedding Matrix",
  "Row 205",
  "Embedding Vector: [0.42, -0.81, 1.24, ...]"
]} />

This retrieval process is called an **Embedding Lookup**.

---

## Why Random Numbers?

Suppose every embedding started as `[0, 0, 0, 0, 0]`.

Every word would look identical. GPT would have no way to distinguish Cat from Dog from Car.

Random initialization gives every token a unique starting point. Training gradually improves those vectors.

<TokenMapping
  title="Embedding for 'cat' — Before vs After Training"
  fromLabel="Stage"
  toLabel="Vector"

    { from: "Before Training", to: "[0.12, -0.81, 0.63, ...]"  },
    { from: "After Training",  to: "[-0.74, 1.08, 0.52, ...]"  },
  ]}
/>

The numbers changed. The meaning emerged.

## Learnable Parameters

Does the Embedding Matrix stay fixed forever?

No. It is a **learnable parameter** — just like the weights inside a neural network. Every prediction slightly adjusts some of its values during training.

The Embedding Matrix learns together with the rest of the model.

## Worked Example

Suppose the tokenizer produces `Dog → 417`.

GPT searches the Embedding Matrix, retrieves Row 417, and obtains `[-0.82, 0.44, 1.73, ...]`.

That vector — not the Token ID — is sent into the Transformer.

## Key Takeaways

- GPT stores all embeddings inside the Embedding Matrix.
- Every Token ID maps to one row in that matrix.
- Embeddings start as random numbers.
- Training gradually transforms them into meaningful vectors.
- The Embedding Matrix is a learnable parameter updated during backpropagation.
